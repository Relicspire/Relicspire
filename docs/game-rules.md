# 1.1 Relicspire ゲームルール

本書は [開発タスク](./tasks.md) の「1.1 ゲームルール」に対応する戦闘仕様である。[企画書](./plan.md) の完全情報、リソースレス、無料リトライ、蘇生制限を前提に、未定義だった計算式と処理順を本書で定める。以下の数値はルールとして採用する値であり、未確定値の仮置きではない。バランス変更時は本書と関連テストを同時に更新する。

キャラクターの初期能力値、各スキル・装備の性能、敵の行動列と報酬は1.2／1.3の成果物で定義する。本書の手計算例はそのための検証用データであり、正式なジョブ・敵データではない。

## 1. 用語と数値の共通規則

| 用語                         | 定義                                                 |
| ---------------------------- | ---------------------------------------------------- |
| TU                           | 行動順を計算する整数の論理時間単位（Time Unit）                    |
| 現在時刻 `now`               | 戦闘開始を0とした経過TU                              |
| 行動可能時刻 `readyAt`       | 次にコマンドを選択できる時刻                         |
| 詠唱完了時刻 `castAt`        | 予約したスキルが発動する時刻                         |
| ディレイ                     | 発動・中断後から次の行動までの硬直                   |
| クールダウン `cooldownUntil` | 同じスキル系統を再使用できる時刻                     |
| 基本行動                     | プレイヤー入力または敵の行動列による行動             |
| 反応行動                     | 反射・反撃・追撃・罠による自動処理                   |
| 処理単位                     | 基本行動または詠唱発動と、それに付随する全反応・蘇生 |

- 時刻、HP、能力値、威力、ゲージは整数。倍率は10000を1倍とする整数（15000＝1.5倍）で保存する。
- `floor` は切り捨て、`ceil` は切り上げ、`clamp(x,a,b)` は範囲内への制限を表す。
- ダメージ・回復・ゲージ削りは全倍率を掛けた後に1回だけ切り捨てる。途中では丸めない。
- 時間の計算は切り上げる。HPは0～最大HP、ゲージは0～最大ゲージに制限する。
- 負の威力・時間・ゲージ削り、範囲外の倍率、非整数データは読み込み時に拒否する。
- イベントの並び順や効果の順番は配列順で保持し、オブジェクトの列挙順に依存させない。

## 2. タイムラインと時間進行

### 2.1 ターンの定義と進行

- 戦闘はタイムラインで行動順を決めるターン制とする。1人の基本行動の開始を1手番と呼び、全員が1回ずつ行動する固定ラウンドは設けない。速度とディレイによって同じ参加者の手番が続く場合がある。
- TUは行動予定・持続時間を比較する論理時間であり、秒への換算や実時間による自動加算は行わない。
- 戦闘開始時、およびコマンド確定後の処理完了時に、現在時刻の未処理イベントを解決する。残っていなければ次のイベント時刻へ `now` を進める。敵行動・詠唱完了・定期効果も順に解決し、次の味方の入力待ちまたは戦闘終了まで進める。
- 詠唱開始はその手番のコマンド確定として扱う。後の詠唱完了は予約済み効果の発動であり、追加の入力手番を発生させない。反応行動や定期効果も入力手番を消費しない。
- 味方の入力待ち・対象選択中は `now` を変更しない。入力に時間制限はなく、敵や持続効果も進行しない。ポーズ、演出再生、アプリの非表示中はイベント処理を休止する。
- 判定は描画フレームから独立する。アイコン移動は確定済みの行動順の変化を示す演出とし、演出速度0.5／1／2倍は判定・手番・TUへ影響させない。
- バーの右端を現在時刻、左方向を未来とし、近い予定ほど右に表示する。表示範囲外の予定も残りTUを数値表示する。
- 生存者の戦闘開始時刻は `readyAt = ceil(100 × 100 / SPD)`。この開始待機は速度変更前の初期能力値から求める。
- 基本行動「待機」は効果なし、基礎ディレイ20 TU、クールダウン0。全生存味方が使用できる。

### 2.2 同時刻の解決順

同じTUのイベントを以下の順で処理する。先のイベントが後の予定を変更・削除した場合、変更後の予定で再判定する。

1. 時間停止解除（参加者順）→通常状態効果・罠の期限切れ（参加者順、付与順）→ブレイク復帰（参加者順）。解除で戻った残り0 TUの予定も、対応する後続段階で処理する。
2. 毒などの定期効果（参加者順、付与順）。同時刻の定期効果全体を1つの処理単位とし、すべてを処理した後、自己蘇生→戦闘終了→続行時のフェーズ移行を判定する。途中の死亡対象への残り定期効果は無効。
3. 詠唱完了（参加者順）。
4. 行動可能（参加者順）。味方なら入力を待ち、敵なら予告済み行動を開始する。

参加者順は味方スロット1→2→3→敵の配置順とする。敵の配置順は戦闘データで固定する。同じ参加者の効果は付与連番順。同時刻でも各処理単位は直列で解決し、後から処理する参加者が先に倒れた場合、その予定は消える。

効果の有効期間は `[付与時刻, expiresAt)` とする。クールダウンは `now >= cooldownUntil` で使用可能。入力待ちで止まっている間に他者の同時刻イベントを先行処理しない。

## 3. 能力値と計算式

### 3.1 能力値

| ID      | 用途               | 最終値の範囲 |
| ------- | ------------------ | ------------ |
| `maxHp` | 最大HP             | 1～99999     |
| `ATK`   | 物理攻撃           | 1～9999      |
| `MAG`   | 魔法攻撃・回復     | 1～9999      |
| `DEF`   | 物理防御           | 0～9999      |
| `MDEF`  | 魔法防御           | 0～9999      |
| `SPD`   | 開始待機・ディレイ | 25～400      |

`能力値 = clamp(floor((基礎値 + 装備加算合計) × (10000 + 強化倍率合計 − 弱体倍率合計) / 10000), 下限, 上限)`。

能力補正は−7500～+30000に制限する。最大HPへの戦闘中の増減は採用しない。3人の基礎能力値は同一とし、具体値とジョブ補正の有無は1.2で定める。

### 3.2 ダメージ・回復・命中

- 物理基礎ダメージ：`max(1, ATK × 威力 / 100 − DEF)`。
- 魔法基礎ダメージ：`max(1, MAG × 威力 / 100 − MDEF)`。
- 最終ダメージ：`max(1, floor(基礎ダメージ × 属性倍率 × 与ダメージ倍率 × 被ダメージ倍率))`。各倍率は保存値を10000で割って使う。無効属性のみ0ダメージ。
- 属性倍率は弱点1.5倍、通常1倍、耐性0.5倍、無効0倍。同じ属性に複数区分を設定できない。
- 与ダメージ補正は加算して倍率を0.25～4倍に制限する。被ダメージ補正も加算し0.1～3倍に制限する。軽減30%なら被ダメージ倍率0.7倍。
- 回復量：`max(1, floor(MAG × 回復威力 / 100 × 与回復倍率 × 被回復倍率))`。回復補正は各0.25～4倍。実回復量は最大HPまでの不足分。
- 攻撃は100%命中、クリティカルとダメージの乱数幅はなし。回避率・命中率ステータスを設けない。
- バリアは最終ダメージを残量分だけ吸収し、残りをHPへ適用する。HPが減らなくても、属性無効でなければ妨害・ブレイク効果は発生する。
- 各攻撃効果は物理／魔法と、無／火／氷／雷／光／闇の属性を1つずつ持つ。無属性は常に通常倍率。複合攻撃は複数の効果に分ける。
- 自傷・反射・毒は明示された固定HPダメージを使い、防御、属性、ダメージ補正、バリアを無視する。戦闘不能になり得る。

### 3.3 速度・ディレイ・時間操作

- 発動後の待機：`delay = max(1, ceil(基礎ディレイ × 100 / 発動直前に保存したSPD))`。
- `readyAt = now + delay`。速度変更は既存の待機・詠唱予定を再計算せず、以後のディレイに適用する。
- 詠唱時間とクールダウンはスキルに設定されたTUをそのまま使い、SPDで短縮しない。
- ノックバックは対象の待機・未処理の行動可能状態なら `readyAt += K`、詠唱中なら `castAt += K`。行動可能状態は後退が1以上なら待機へ戻す。基本行動発動の効果・反応を処理中の場合は、後退TUを終了待機への加算として蓄積する（11.2節）。`K = ceil(基本後退TU × (10000 − 後退耐性) / 10000)`、耐性は0～10000。
- ブレイク中・戦闘不能中へのノックバックは無効。
- 前進は待機中の `readyAt` または詠唱中の `castAt` を指定TU減らし、下限を `now + 1` とする。ブレイク中・戦闘不能中には無効。
- 直接の前進・後退はSPD補正を受けない。時間停止中は凍結した残りTUに同じ計算を適用する。

## 4. 行動状態、詠唱、クールダウン

| 状態     | 進入条件                         | 終了・遷移                           |
| -------- | -------------------------------- | ------------------------------------ |
| 待機     | 戦闘開始、発動後、中断後、蘇生後 | `readyAt` で行動可能へ               |
| 行動可能 | 待機満了                         | 確定した即時行動を発動、または詠唱へ |
| 詠唱     | 詠唱時間が1以上のスキルを確定    | `castAt` で発動、中断なら待機へ      |
| ブレイク | 生存敵のゲージが0になる          | 60 TU後に待機へ                      |
| 戦闘不能 | HPが0になる                      | 許可された蘇生のみ待機へ             |

時間停止は上記状態に重なる独立状態。状態ごとに有効な行動予定は最大1件とする。

- コマンド確定時に生存、習得、対象、クールダウン、行動禁止を検証する。不正な入力では時間・状態を変更しない。
- 確定時に `cooldownUntil = now + 基礎クールダウン` を設定する。上位版へ置換される同系統スキルはクールダウンIDを共有する。
- 詠唱は `castAt = now + 詠唱TU` としてスキルと対象を予約する。予約後に手動で変更できない。
- 能力値は11.5節の参照時点で計算する。発動後からディレイを開始し、詠唱時間はディレイに含めない。
- 発動時に単体対象が不適格なら効果は不発、クールダウンは残り、通常のディレイが発生する。対象を自動で選び直さない。全体対象は発動直前の適格な全員を一度だけ固定し、各効果で再選択しない（11.4節）。
- 詠唱キャンセル効果を受けた場合は予約を削除し、固定30 TUの待機へ移る。クールダウンは返却しない。詠唱していない対象にはキャンセル効果だけが無効。
- 戦闘不能・ブレイクでも詠唱を削除する。この場合は30 TUの中断待機を追加せず、各状態の復帰規則を使う。
- 通常待機へのキャンセル効果、詠唱中の追加コマンド入力は無効。反応行動は待機・詠唱中にも発生できる。

## 5. ブレイク

- ブレイクゲージを持つのは敵だけ。戦闘開始時は敵データに定める最大値で満タン。
- 攻撃のゲージ削り：`floor(基本削り値 × 弱点補正 × (10000 − ブレイク耐性) / 10000)`。弱点補正は弱点なら2倍、その他1倍。属性無効なら削り0。耐性は0～10000。
- HPダメージの後に削りを適用する。戦闘不能になった敵への削りは処理しない。
- 0になった直後に待機・詠唱を削除してブレイクへ移る。予定していた敵行動を1つ消費し、次の行動列要素へ進む。詠唱開始時に消費済みなら追加消費しない。
- ブレイク時間は60 TU。ブレイク中は基本・反応行動が不能、被ダメージ倍率に+5000（+50%）を加える。追加ゲージ削り・再ブレイクは無効。
- 復帰時にゲージを最大値へ戻し、`readyAt = now + ceil(100 × 100 / SPD)` とする。これをタイムライン最後尾への後退として表示する。
- ブレイク復帰時に次の予告を更新する。ゲージの自然回復・耐性の累積増加はなし。明示されたゲージ回復効果だけが最大値まで回復でき、ブレイク中には無効。
- 永久ブレイク耐性は10000で表す。詠唱キャンセル耐性は別の真偽値であり、ブレイク耐性から推測しない。

## 6. バフ／デバフと持続効果

| 分類           | 代表例                       | ルール                  |
| -------------- | ---------------------------- | ----------------------- |
| 能力補正       | 攻撃強化、速度低下           | 能力値の計算へ加算      |
| 与／被効果補正 | ダメージ増加、軽減、回復増加 | 各倍率へ加算            |
| 定期HP効果     | 毒、継続回復                 | 20 TUごとに定義量を適用 |
| 防御・反応     | バリア、かばう、反射、反撃   | 処理順は7節             |
| 制御           | 挑発、時間停止               | 対象・時間進行を変更    |
| 設置・連携     | 罠、追撃                     | 条件一致時に反応        |
| 復帰予約       | 自己蘇生                     | 戦闘不能時に1回消費     |

- 各効果に `familyId`、強度、持続TU、解除可能か、付与者、付与連番を設定する。強化／弱体は別系統とする。
- 同じ対象の同系統は1件だけ。再付与では既存の強度・付与者・付与連番を維持し、通常時は `expiresAt = now + 新しい持続TU`、時間停止中は保存した残り持続TUを新しい持続TUへ更新する。強度を加算・交換しない。残量・回数も補充しない。
- したがって強度を変更するには既存効果を解除・終了させてから再付与する必要がある。異なる系統は共存し、数値補正は加算する。
- 定期効果は初回付与の20 TU後から20 TU刻み。同系統の再付与で発動周期をリセットしない。期限と同時刻の発動は期限切れが先なので発生しない。
- 戦闘不能になるとすべての状態効果と本人の設置罠を削除する。自己蘇生だけは削除前に発動資格を保存し、その処理単位の末尾で消費する。
- ブレイク中もタイムラインが進んだTU分だけ効果の期限、定期効果、クールダウンが経過する。時間停止中の扱いは7.5節。
- 解除は効果に指定した強化／弱体区分と解除可能フラグに従う。複数件解除なら付与連番順。ブレイクと戦闘不能は解除スキルで消せない。
- 持続TUは1以上。バリアは残量0、反射・罠・自己蘇生は使用回数0でも即座に終了する。

## 7. 特殊効果と処理順

### 7.1 1つの処理単位

1. 敵の基本行動開始前だけ罠を解決し、行動者の資格を再確認する。開始できる場合は挑発を適用して元の対象を確定する。詠唱ならこの対象を予約し、詠唱完了時には発動資格と対象の適格性だけを再確認する。
2. 発動直前に対象集合と行動者の能力値を保存し、スキルの効果配列順に処理する。各効果内は参加者順、連続ヒットはヒット順。
3. 攻撃1ヒットごとに、元の対象の適格性確認→かばうによる被弾者の決定→被弾直前の反射資格の保存→HPダメージ→戦闘不能判定→生存対象へのゲージ削り・ブレイク→ノックバック→詠唱キャンセル→付随する状態付与の順で処理する。
4. 各ヒットから発生する反射→反撃をそのヒットの直後に処理する。
5. 基本行動の全効果後に追撃を参加者順で処理する。
6. 予約した自己蘇生を参加者順で処理する。
7. 戦闘終了を判定し、続行ならフェーズ移行を評価して11.2節の優先順で終了待機を確定する。死亡・ブレイク・蘇生による復帰予定を通常ディレイで上書きしない。

基本行動の発動後は行動者が途中で倒れても、確定済みの残り効果を最後まで処理する。対象が途中で倒れた場合、その対象への残り攻撃・通常回復・状態付与は無効。蘇生効果は別扱い。

反応から反射・反撃・追撃・罠は発生させない。反応はクールダウン・ディレイを使わず、実行者自身の待機・詠唱予定を変更しない。ただし反応の妨害効果は対象の詠唱を中断できる。各反撃・追撃効果の発動は1処理単位につき1回まで。反撃・追撃・罠は発動時に実行者が戦闘不能・ブレイク・時間停止なら無効。反射だけは被弾直前に資格を保存するため、そのヒットによる戦闘不能・ブレイク・時間停止・効果解除では取り消さない。

反撃・追撃・かばうは待機・行動可能・詠唱中に利用できる。「行動可能」状態へ到達していることを発動条件にしない。基本行動の処理末尾では、行動者が時間停止された場合の終了待機も11.2節で決めて残りTUとして凍結する。

### 7.2 挑発・かばう

- 挑発は敵への弱体効果。敵の敵対単体スキルの対象を付与者へ変更し、全体・自身対象には作用しない。付与者が生存していなければ無効。
- 挑発による変更は罠の解決後、即時行動の発動直前または詠唱開始時に1回だけ適用する。詠唱開始後の元の対象は固定し、挑発の付与・解除・付与者の戦闘不能で変更しない。予約対象が発動時に戦闘不能なら4節の不発規則を使う。
- かばうは元の対象が適格な場合に、味方単体への攻撃効果を、かばう付与者へ移す。全体攻撃・固定HPダメージ・回復・蘇生には無効。各ヒットの命中直前に、その時点のかばう効果と付与者の資格を確認する。詠唱開始時には被弾者を固定せず、詠唱中に付与・解除されたかばうも反映する。
- かばう付与者が戦闘不能・ブレイク・時間停止なら元の対象へ攻撃する。移し替えは1回だけで、かばうの連鎖を起こさない。
- 攻撃に付随するゲージ削り・妨害・弱体も移し替え後の対象へ適用する。

### 7.3 反射・反撃・追撃

- 反射は被弾直前に反射効果の残り回数が1以上で、被弾者が生存かつブレイク・時間停止していない場合に資格を保存する。かばうが成立した場合はかばう付与者の反射だけを参照する。対象自身への魔法HPダメージが1以上の場合、実際に失ったHPの50%を切り捨て、攻撃者へ固定HPダメージとして返す。HP損失が0なら反射せず回数も消費しない。HP損失が1なら反射値0でも1回分消費する。元の被害は減らさず、HP損失が1以上の1ヒットで1回分消費する。対象が倒れてもそのヒットの反射は発生する。
- 反撃は攻撃によってHPを1以上失い、そのヒット後に生存かつブレイク・時間停止していない防御者が、反射処理後も生存している攻撃者へ定義された攻撃効果を実行する。
- 追撃は自分以外の味方が基本行動で敵へHPダメージを与えたときに候補を記録する。対象はその行動で最初にHPダメージを与えた敵に固定する。全効果終了後に基本行動者・追撃者・対象が生存している場合だけ発動し、対象が倒れていても他の敵へ変更しない。待機・回復・不発・反応行動には発生しない。
- 反撃・追撃は通常のダメージとゲージ削りの計算を使うが、挑発・かばうを再適用しない。

### 7.4 罠

- 罠は設置者ごとに1個。設置し直すと古い罠を削除し、新しい性能・期限・付与連番で置換する。状態効果の同系統延長とは別の設置操作である。
- 生存敵が基本行動を開始する直前に、敵を対象とする罠を設置順で発動する。詠唱技は詠唱開始前に発動し、詠唱完了では発動しない。
- 罠は1回で消費する。各罠の処理後に自己蘇生と戦闘終了を判定する。敵が倒れた／ブレイクした場合は基本行動を開始しない。
- 各罠の解決後、敵が戦闘不能・ブレイク・時間停止、または `readyAt > now` なら残りの罠判定を打ち切る。未発動の罠は保持する。時間停止・ノックバックによる延期では行動列・クールダウンを消費せず、次回開始前に残りの罠を判定する。ノックバックで `readyAt > now` になった場合も基本行動を延期する。詠唱前なのでキャンセル効果だけでは開始を防げない。
- 設置者がブレイク・時間停止中なら発動・消費しない。設置者の戦闘不能では罠を削除する。

### 7.5 時間停止

- 対象の待機、詠唱、ブレイク復帰、クールダウン、対象に付いている状態効果の期限・定期発動、本人の罠の期限を凍結する。時間停止自体の期限だけは戦闘全体のTUで経過する。
- 凍結開始時に各予定までの残りTUを保存し、解除時に `now + 保存した残りTU` へ戻す。停止中に付与された効果も付与直後から残り時間を凍結する。新規付与・再付与・解除・死亡の具体処理は11.3節に従う。
- 時間停止中も他者からのダメージ・回復・ゲージ削り・解除・キャンセルを受ける。ブレイクした場合は残り60 TUの復帰予定を凍結する。
- 被弾前から停止中の対象は反射資格を得ず、反撃・追撃・罠も発動しない。同じヒットで停止が付与された場合、保存済みの反射だけは発生する。攻撃を受けても停止は解除しない。
- 再付与は停止終了時刻を `now + 新しい持続TU` に更新する。凍結中の予定を二重にずらさない。
- 時間停止の無効耐性は真偽値で定義する。無効なら他の付随効果だけを通常処理する。

### 7.6 蘇生

- 他者蘇生はクレリックの指定上位スキルだけ。自分以外の戦闘不能味方1人を対象とする。
- 自己蘇生はバーサーカーの指定上位スキルによる事前付与だけ。戦闘不能中にコマンドを選ぶことはできない。
- 蘇生HPは `max(1, floor(maxHp × スキルの蘇生率 / 10000))`。蘇生率は1～10000。
- 蘇生後は状態効果なし、詠唱なし、固定50 TUの待機。戦闘不能中もクールダウンは経過し、蘇生でリセットしない。
- 他者蘇生はスキルの効果配列内の位置で即座に解決する。自己蘇生は処理単位の末尾に1回だけ発動する。両方が同じ対象に成立した場合、先に他者蘇生で復帰した対象の自己蘇生予約は消費・破棄し、二重の回復や待機再設定を行わない。蘇生前の同じ処理単位内の追加攻撃は戦闘不能対象として無効。
- 敵、装備、アイテム、通常回復に蘇生を持たせない。全滅時でも自己蘇生の予約があれば処理してから敗北を判定する。

## 8. 敵の予告と完全情報性

- 戦闘判定に乱数を使用しない。ダメージ、対象、状態付与、報酬は固定。演出専用乱数は戦闘状態に影響させない。
- 敵の行動は固定配列とループ位置で定義する。HP条件によるフェーズ変更は閾値と移行先を事前表示する。
- 次の行動のスキル、対象、開始・発動時刻、ディレイ、クールダウン、弱点、耐性、ゲージ、状態効果を表示する。
- 対象選択は明示された規則（例：現在HPが最小の味方）を用い、同値なら味方スロット順。開始前は状態変更のたびに予告を再計算し、詠唱開始時に固定する。
- 行動列要素は行動開始時に消費する。不発・詠唱キャンセルでも戻さない。開始前ブレイクによる消費は5節のとおり。
- フェーズ変更は基本行動・詠唱発動・各罠・同時刻の定期効果群の処理単位末尾に、自己蘇生と戦闘終了判定の後で続行時だけ評価する。既存の詠唱を維持し、次回行動から新しい列を使う。閾値は降順で評価し、到達した最深フェーズへ移行する。
- 敵の予定スキルがクールダウン中なら、使用可能時刻まで待機を延長して予告する。敵用スキル構成はこの待機も含めて検証する。
- プレイヤーの確定前プレビューは、現在状態に対するダメージ、ゲージ削り、妨害、反応、次回時刻を本判定と同じ計算で表示する。将来の状態変化がある場合は現在値での予測であることを示す。

## 9. 戦闘終了・逃走・再挑戦

永続保存の確定・復旧・画面遷移は [保存・復旧・画面遷移仕様](./save-recovery-navigation.md) を適用する。戦闘結果の論理確定と、進行・報酬の保存完了を区別する。

| 条件                              | 結果                           |
| --------------------------------- | ------------------------------ |
| 全敵HP0、味方が1人以上生存        | 勝利                           |
| 全味方HP0、敵が1体以上生存        | 敗北                           |
| 全敵・全味方HP0（自己蘇生処理後） | 相打ちによる敗北。報酬なし     |
| 続行中に逃走を確定                | 即時終了。成功率100%、報酬なし |

- 勝敗は処理単位が完了した後に判定する。反射による相打ちを勝利扱いにしない。戦闘終了後の予定イベントはすべて破棄する。
- 戦闘開始前に編成、所持品、ポイント、階層解放、討伐済みフラグ、探索位置のスナップショットを保持する。戦闘開始時は味方HP全快、状態効果なし、クールダウン0。
- 逃走／敗北では開始前状態を復元し、HP全快で遭遇直前へ戻る。装備・ポイント・進行の損失はない。拠点へ戻って無料でリビルドできる。
- リトライは演出・入力待ち・敗北画面から実行可能。開始前状態を復元して同じ戦闘を時刻0から初期化する。同じ編成・入力なら同じ結果になる。
- 逃走・リトライは現在の処理単位完了後、次のイベント前に適用する。その処理で勝敗が確定した場合は勝敗を優先し、勝利後のリトライは不可。
- 勝利報酬と討伐済みフラグ、次階層解放は同じ永続更新にまとめ、敵IDごとに一度だけ付与する。味方HPは全快にし、戦闘効果・クールダウンは持ち越さない。
- 保存失敗時は同じ更新を再試行できるよう保持し、二重付与を防ぐ。保存完了前は次操作を許可せず、再試行または未保存勝利の明示的放棄を選ぶ。保存・復旧仕様3節をタスク4で実装する。
- 戦闘状態そのものは永続保存しない。戦闘中の設定保存は開始前の確定進行と設定だけを保存し、リトライで設定を巻き戻さない。戦闘中の再読み込みは最後に保存した戦闘前状態から再開する。

## 10. 手計算例と受け入れ条件

### 10.1 開始から勝利まで

味方3人は全員HP100、ATK40、DEF10、SPD100。敵1体はHP90、ATK30、DEF10、SPD100、ゲージ100、弱点なし、各耐性0。他の補正はなし。

味方は即時物理攻撃（威力100、削り10、基礎ディレイ100、クールダウン0）を使用する。敵は味方スロット1への即時物理攻撃（威力100、削り0、基礎ディレイ100）を繰り返す。

| TU  | 処理           | 結果                                                           |
| --- | -------------- | -------------------------------------------------------------- |
| 0   | 全員の開始待機 | `ceil(100 × 100 / 100) = 100`、全員TU100予定                   |
| 100 | 味方1が攻撃    | `40 × 100 / 100 − 10 = 30`、敵HP60、ゲージ90、味方1はTU200予定 |

敵の同時刻行動は勝利によって破棄される。味方3人のHPは100のまま。報酬更新は1回だけ行う。

## 11. 境界条件の確定仕様（タスク1.4）

本節は既存の一般則の適用順を具体化する。現在の制作・実装範囲は11.7節に限定し、範囲外の一般則を根拠に未使用機能を追加しない。

### 11.1 同時刻とイベントの再評価

2.2節の各段階を戦闘全体へ適用し、参加者ごとに全段階をまとめて処理しない。時間停止解除で凍結予定を復元した後、期限切れ、ブレイク復帰、定期効果、詠唱完了、行動可能の順に進む。例えば期限が残り0の状態は解除直後の期限切れ段階で削除し、その状態の定期効果を発動しない。

イベントを処理するときは対象の現在状態と予定時刻を再検証し、削除・後退された古いイベントは実行しない。解除後の残り0 TUは現在時刻で一度だけ処理し、1 TUを自動追加しない。処理済みイベントはその予定IDで再実行しない。定期効果は次回を20 TU後へ更新する。新しい前進では下限1 TUを維持するため、その操作だけで同時刻の無限再実行を作らない。

フェーズ変更は2.2・8節の処理単位末尾だけに行う。毒で閾値を越えても同時刻の他の定期効果と自己蘇生が完了するまで移行しない。HP0なら勝敗を先に確定し、死亡敵のフェーズを更新しない。

### 11.2 時間操作と行動終了の優先順

| 対象の状況 | 後退 | 前進 |
| --- | --- | --- |
| 待機、手番到達済みだが未処理 | readyAtに後退量を加える | 待機だけ短縮、下限now+1。手番到達済みには無効 |
| 詠唱、発動直前の未処理詠唱完了 | castAtに後退量を加える | castAtを短縮、下限now+1 |
| 基本行動の効果・反応を処理中 | pendingKnockbackへ後退量を加算 | 無効。まだ終了待機が存在しないため |
| ブレイク、戦闘不能 | 無効 | 無効 |

後退耐性による切り上げは各後退効果ごとに行って合算する。時間停止中も同じ対象状態に対して保存した残りTUを操作し、前進の残りTU下限は1とする。罠は敵の開始前なのでreadyAtを後退させ、延期時には通常ディレイを新設しない。詠唱発動開始後は詠唱状態を終了し、以後の後退はpendingKnockbackへ入れる。

基本行動・詠唱発動（対象不適格による不発を含む）の末尾は以下を適用する。

1. 戦闘終了なら予定をすべて破棄する。
2. 行動者が戦闘不能なら待機を作らない。
3. 行動者がこの処理単位内で一度でも戦闘不能になり蘇生した場合は、蘇生時に作った固定50 TU待機を維持する。pendingKnockbackは破棄する。
4. 行動者がブレイクなら復帰予定を維持し、通常ディレイも追加後退も作らない。発動開始済みの行動について行動列を二重に消費しない。
5. その他は `待機TU = max(1, ceil(基礎ディレイ × 100 / 保存SPD)) + pendingKnockback`。通常時はreadyAt=now+待機TU、時間停止中は待機TUを凍結して保存する。

pendingKnockbackはこの処理単位内だけ有効。蘇生直後の人物に後続効果で新しい後退を与えた場合は、その時点の固定待機を後退させ、その更新も維持する。処理中に時間停止を付与されても発動済みの残り効果は完了し、反応資格は従来どおり判定する。

詠唱キャンセルは発動開始前だけ有効。停止中のキャンセルは詠唱予定を削除して残り30 TUの待機を凍結し、CDを維持する。発動開始後はキャンセル無効で、HPダメージなど他の効果だけを処理する。

### 11.3 時間停止・効果延長・死亡

- 停止開始時は有効な予定の残りTUを `max(0, 予定時刻-now)` で保存する。凍結予定を通常イベントキューから外し、停止の終了予定だけを残す。
- 新規状態付与では残り持続TUを設定し、毒の初回残り発動TUは20とする。再付与では残り持続TUだけを新しい持続へ置換し、定期発動までの残りTUを維持する。
- 停止自体の再付与は終了時刻をnow+新しい持続へ更新するだけ。既存の凍結予定を再取得・二重加算しない。
- 停止の期限切れ・解除では保存予定をnow+残りTUへ復元する。ほかの状態を解除した場合はその状態の保存予定も消し、解除時に復活させない。
- 停止中の死亡では停止・全状態・罠・行動予定を削除する。CDだけは死亡時刻+保存した残りTUで通常の絶対時刻へ戻し、以後は戦闘不能中も経過する。自己蘇生資格は死亡直前に確保する。
- 停止中のブレイクは残り60 TUの復帰を凍結する。解除後に60 TU経過して復帰する。ブレイク復帰で作る待機も、その時点のSPDを使う。

### 11.4 対象束縛と複合効果

コマンド確定時に選択対象ID・属性選択を保持する。単体の詠唱対象は変更しない。発動直前にスキル全体の必須対象と、全体対象集合を確定する。その後、各効果実行時に生存／戦闘不能などの適格性だけを再検証する。対象の入れ替えや集合への追加を行わない。

| Effectの対象束縛 | 適用規則 |
| --- | --- |
| selected | 確定した単体対象ID |
| all-allies / all-enemies | 発動直前に固定した対象ID配列 |
| self | 行動者ID。死亡中の回復・状態付与は無効 |
| hit-recipient | 直前の攻撃で実際に被弾したID。かばうを反映し、攻撃不成立なら付随効果も不成立 |

攻撃に「→毒」「→弱体」「→解除」「→後退」「→キャンセル」が付く場合は、同じ攻撃Effectの付随効果としてhit-recipientへ束縛する。後退・キャンセル・状態付与・解除の順（同分類内は記載順）で処理してから反射・反撃へ進む。単独の時間遅延・挑発・状態付与には先行攻撃を要求しない。ゲージ削りはダメージ直後。

回復→解除のように攻撃以外が連続する場合は、独立Effectとして記載順に実行する。浄化の光は固定した味方集合全員の回復を参加者順に処理し、その後同じ集合全員の解除を参加者順に処理する。全体対象は生存者だけなので発動時点の死者を含めない。

聖断・速度奪取はselectedを必須対象とし、発動直前に不適格なら全Effectが不発。適格ならその後の敵死亡でself効果を取り消さない。ただし行動者自身が死亡すればself回復・強化は無効。通常回復は新しい対象を選び直さず、蘇生Effectのみ死者を適格とする。将来の複合蘇生を設計する場合も、発動時点で集合に含まれたIDへの後続回復だけが成立する。

### 11.5 能力・条件の参照時点

基本行動の発動直前（詠唱なら完了時、不発でも同じ時点）に、行動者のATK・MAG・SPD・HP・最大HP・与ダメージ／回復補正を保存する。全Effectはこの行動者スナップショットを使い、背水条件も同時点で判定する。後から同じ行動で自身を強化・回復しても保存値を変えない。

各被弾・回復の対象DEF・MDEF・属性倍率・被効果補正は、その効果の直前の現在値を参照する。かばう後は被弾者の値を使う。ブレイクを起こした一撃自体にはブレイクの被ダメージ増加を遡及適用しない。

反撃・追撃・罠はそれぞれの発動直前に実行者スナップショットを別途保存し、元の基本行動の能力を使わない。反射はHP損失を記録した値から計算し能力値を参照しない。回数・バリア残量などの消費可能量は各ヒットの現在残量を参照する。

### 11.6 無効・反応・付与者

- 属性無効の攻撃はHPダメージ・削り・全付随効果が0／不成立。独立の解除・時間操作・状態付与は属性判定を持たず、対象適格性と固有耐性だけで成立する。
- バリアでHP損失が0でも属性が無効でなければ削り・妨害・付随効果は成立する。反射・反撃・追撃はHP損失0では候補を作らず、反射回数も消費しない。
- 固定HPダメージ（現行は毒・反射）は属性・防御・バリア・ダメージ補正を無視し、かばう・反射・反撃・追撃・ゲージ削りを発生させない。
- 反射処理後に元の攻撃者が死んでいれば、そのヒットの反撃は不発。反応の相互連鎖は禁止したまま、元の基本行動の残りEffectは完了する。
- 同系統再付与は付与者が別人でも強度・付与者・付与連番・残量を維持して期間だけ置換する。死亡した付与者を新しい付与者へ差し替えない。
- 対象上の効果は付与者死亡だけでは削除しない。毒・能力補正は期限まで有効。挑発は付与者が死んでいる間に対象変更せず、かばうは付与者死亡・ブレイク・停止中に無効だが効果自体は残す。付与者の復帰後に有効性を再判定する。対象本人死亡では6節どおり削除する。
- 表示には実際の付与者、強度、残量、有効／一時無効を示し、別人による延長を付与者変更として表示しない。

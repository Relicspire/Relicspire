# 第1階層の正式コンテンツと検証

`src/content/release.json` が正式な GameRelease の唯一の収録データ。成長・編成・報酬仕様2～3節と階層仕様3.1・4.1～4.3節の確定値を使用する。全48ノード、初期装備6種、遺物5種、守護者5体、ボス1体、探索10ノードを収録する。全編の10階層・60敵・50遺物の正規IDと固定報酬を保持し、実戦範囲は第1階層に限定する。ボス討伐で第2階層を解放するが、未収録階層への移動は許可しない。

正式入口は既存の `bundledRelease()` が取り込む。製品用の buildId・配信状態キー・PWA準備は8.1～8.2で接続する。この検証では製品の準備判定を変更しない。

## 開発用の試遊

1. `npm run dev` を起動する。
2. `/Relicspire/playtest.html` を開き「冒険を始める」を選ぶ。
3. 伝言板、無料リビルド、祠、予告碑、ボスを試す。
4. 最初から試すときはセーブ管理の「新規開始」で確認して確定する。

開発サーバー専用。通常ビルドは `index.html` だけを入口にし、試遊HTMLをdistへ配信しない。試遊DBは `relicspire-playtest-v1`、製品DBは `relicspire` で分離する。試遊だけに固定の開発版配信キーを設定する。Web Locks・保存の原子的な版照合・復旧UIは実装済みの管理器を通る。終了時に所有権を解放する。製品起動と同じ所有権ロックなので同時プレイはしない。

## 検証した範囲

- `release.test.ts`：正式カタログの構造、参照、所持上限、初期編成、全編メタデータを検証。
- `specification.test.ts`：確定仕様表の全48ノードと名称・詠唱・D・CD・威力・削り・回復を照合。固定行動列と属性・妨害耐性を検証。
- `loop.integration.test.tsx`：実App、編成・探索・戦闘・報酬・復旧UI、実状態管理、fake-indexeddbを通る画面一巡。守護者・ボスの勝敗は正式戦闘エンジンで計算し、勝利状態を直接注入しない。Pixi描画のみ模擬する。
- 実ブラウザの開発用試遊：新規開始→伝言板→ウィザードのAを解除してB1・B2を習得→保存→ワープ→剣の守り手を討伐→遺物保存→討伐済み祠→予告碑→門衛ゴーレムを討伐→報酬保存→拠点帰還。通常演出の雷選択・ブレイク・次の入力待ちと、第2階層未収録の移動禁止を確認。報酬画面は390px幅で横スクロールなし。

画面一巡の自動テストはhappy-dom上の統合テストであり、製品PWAを使うブラウザ自動E2Eではない。実ブラウザの一巡は手動操作による確認。正式な配信、複数タブ、ブラウザ終了からの復帰は8.2・7.2で検証する。

## 初期予算での攻略計測

初期装備のまま各人3ptでA1+A2またはB1+B2を習得。雷術は雷を選択。回復役は生存味方のHP比が65%未満なら回復し、それ以外は通常攻撃。CD中の攻撃役も通常攻撃でつなぐ。盾の構え・装備集中・遺物は使わない。全編成が6体すべてに勝利し、3人とも生存することを `balance.test.ts` で検証する。

| 編成 | ボス入力手番数 | ボス終了TU | 守護者入力手番数 |
| --- | --- | --- | --- |
| ナイトA・ウィザードB・クレリックA | 7 | 242 | 4～6 |
| バーサーカーB・シーフA・クレリックA | 9 | 288 | 5～7 |
| レンジャーA・ウィザードB・クレリックA | 7 | 242 | 4～5 |
| 初期編成（火を避けて通常攻撃＋回復） | 11 | 384 | 7～10 |

論理TUは実プレイ時間ではない。初期編成から雷にリビルドするとボスは11手→7手となり、ヒントに合わせた変更の効果を確認できる。短い戦闘でも初期装備・固定性能を崩さず、基礎仕様の数値を変更しない。

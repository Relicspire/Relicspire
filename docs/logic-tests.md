# 3.4 ロジックテスト

`npm test`でVitestを実行する。UI・PixiJS・Zustand・IndexedDBを使用せず、純粋なゲームロジックを検証する。CIはテスト成功後にビルド・デプロイへ進む。

## 検証対象

| タスク | テストと固定する契約 |
| --- | --- |
| 計算式の境界値 | `src/game/battle/calculations.test.ts`で能力値の上下限、ディレイの切り上げ・最低1 TU、属性倍率、物理／魔法の防御参照、最低ダメージ、HP50%の背水条件、補正倍率の上下限、回復・ゲージ削りの丸めを検証 |
| 処理順・同着・相打ち | `src/game/battle/engine.test.ts`で停止解除→期限切れ→毒→詠唱→手番、同着の人物順、全定期効果後のフェーズ更新、反射・毒の相打ち、勝敗判定前の回復・自己蘇生を検証 |
| 全状態効果 | 同ファイルの「全状態系統のライフサイクル」で16系統すべての新規付与、期限直前の保持、再付与、自然終了、死亡者への付与拒否を検証。再付与は強度・付与者・付与順・周期・消費済み回数・解除可否を保持する。各状態の戦闘効果は能力補正・防御・挑発・かばう・反射・反撃・追撃・毒・蘇生・停止の個別テストで検証 |
| 妨害の相互作用 | 詠唱キャンセルの固定30 TU、ブレイクの固定60 TUと復帰待機、停止中の予定凍結、停止中の死亡によるCD復元、蘇生後の固定50 TU、停止解除・解除スキルによる凍結解除を検証 |
| 編成 | `src/game/party/party.test.ts`で同職3人、個人予算、集中装備・所持数超過・遺物の唯一性、プリセット不整合の拒否と明示修復、戦闘開始時の共通検証を実施 |
| 再現性 | 同じ入力列でUIなしのサンプル戦闘を勝利まで再生し、セッション全体・構造化ログ・タイムライン・報酬候補を比較。自動進行と処理単位ごとの進行も一致する |
| 実時間・演出速度からの独立 | Vitestの仮想時計で開始年月、1時間以上の入力待ち、処理単位間の演出待ちを変更する。入力待ちではTU・手番が進まず、終了時の全状態・ログ・結果と入力列が一致する |

## ゲームルール11.8節との対応

| 境界例 | 対応するテスト |
| --- | --- |
| B01〜B03 | 停止解除時の毒の期限優先、残り0の詠唱、同時毒とフェーズ移行 |
| B04〜B06 | 未処理の同着敵への後退、罠による行動開始延期、行動中の後退加算 |
| B07〜B09 | 自己蘇生の待機保持、反撃ブレイクの二重列消費防止、予約対象死亡の不発 |
| B10〜B12 | 停止中の再付与、死亡時のCD復元、停止中の詠唱キャンセル |
| B13〜B16 | かばう後の毒の対象、聖断の末尾回復、発動前SPD、毒の元付与者と強度の保持 |
| B17 | 死亡した挑発者を延長で変更せず、期限切れ後の新規付与だけ変更 |
| B18 | 無効属性はダメージ・削り・付随妨害すべて不成立 |
| B19 | バリアは将来対応のため振る舞いテストの対象外。現行の読み込みでは未対応として拒否 |
| B20〜B21 | 反射値0でも回数消費、反射による攻撃者死亡で反撃抑止、自己蘇生の末尾処理 |
| B22 | `src/game/data/validation.test.ts`でバリア・継続回復・自傷・ゲージ回復・複数敵・複数ヒットを拒否。未知JSONの検証と読み込み例外を確認 |

テスト用コンテンツは合成カタログである。正式な全遭遇データの投入と全編バランス調整、保存の原子性、画面・描画との接続は後続タスクで検証する。

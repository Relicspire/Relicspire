# Relicspire 開発タスク

本書は [`plan.md`](./plan.md) を実装可能な作業単位へ分解したタスクリストです。上から順に進めることを基本とし、仕様変更時は関連するデータ、テスト、ドキュメントも同時に更新します。

## 0. 完成条件（Definition of Done）

- [ ] PC・モバイルの主要ブラウザで、拠点から第10階層クリアまで進行できる
- [ ] 3人編成、8ジョブ、各2系統のスキルツリー、6装備枠、プリセットが機能する
- [ ] 全10階層に階層ボスを実装し、各階層の任意の遺物守護者とユニーク遺物を実装する
- [ ] 完全情報型タイムライン、ディレイ、クールダウン、詠唱妨害、ブレイク、バフ／デバフ、戦闘不能／蘇生が仕様どおり動作する
- [ ] 勝利報酬、討伐済みフラグ、階層解放、セーブ、ロード、セーブデータ移行が機能する
- [ ] 敗北・逃走・再挑戦に恒久的なペナルティがない
- [ ] 初回読み込み後、必要なゲームアセットをオフラインで利用できる
- [ ] 自動テスト、型チェック、Lint、ビルドが通り、GitHub Pagesへ自動デプロイできる
- [ ] セーブ破損、進行不能、操作不能、再現性の高いクラッシュが残っていない

## 1. P0: 仕様を実装可能な粒度にする

実装前に決める項目です。成果物は `docs/` 配下の仕様書と、後でTypeScriptへ移せる表形式データにします。

### 1.1 ゲームルール

- [ ] タイムラインの時間単位、進行速度、同着時の解決順、入力待ち中の時間停止有無を決める
- [ ] 基礎ステータス、ダメージ、回復、命中、弱点、軽減、速度、ディレイの計算式と丸め規則を決める
- [ ] 通常行動、詠唱、クールダウン、ノックバック、詠唱キャンセル、ブレイクの状態遷移を決める
- [ ] ブレイクゲージの増減、ブレイク時間、復帰位置、耐性の扱いを決める
- [ ] バフ／デバフの分類、上書き、持続時間、解除、行動不能中の経過規則を決める
- [ ] 挑発、かばう、反射、反撃、追撃、罠、時間停止、自己蘇生／他者蘇生の処理順を決める
- [ ] 戦闘終了条件、相打ち、全滅、逃走、リトライ時の状態復元規則を決める
- [ ] 乱数の使用範囲を決める。完全情報性を損なう乱数は排除するか事前表示する

### 1.2 成長・編成・報酬

- [ ] 3キャラクターの初期HP・能力値と、ジョブによる補正の有無を決める
- [ ] 8ジョブそれぞれの2ルート分のスキルツリー、必要ポイント、前提、上位自動置換グループを定義する
- [ ] 初期スキルポイント、ボス報酬、最終的な総ポイントを決める
- [ ] 初期装備の種類・個数・性能と、装備効果の重複可否を決める
- [ ] 全ユニーク遺物の性能、入手元、重複不可条件を定義する
- [ ] 不正なスキル割り振りや同一ユニーク遺物の重複装備を防ぐ編成検証規則を決める
- [ ] プリセット保存数、名称制限、未入手装備を含む旧プリセットの扱いを決める

### 1.3 全10階層のコンテンツ

- [ ] 各階層のテーマ、マップ経路、イベント、ボス、守護者、報酬を一覧化する
- [ ] 各階層ボスの行動ローテーション、予告情報、弱点、ブレイク条件、攻略意図を定義する
- [ ] 各階約5体を目安に、遺物守護者の行動・報酬・配置を定義する
- [ ] 守護者を無視してボスへ直行でき、討伐済み敵が再出現しない進行規則を定義する
- [ ] 伝言板のヒント文と、各ヒントが示す攻略要素を対応付ける
- [ ] エンディング、クリア後の状態、再訪可否を決める

**完了条件:** 未確定値を仮置きせず、1戦を最初から最後まで手計算できる仕様と、第10階層までのコンテンツ表がある。

**完了条件:** クリーン環境で `npm ci` 後に全品質チェックと本番ビルドが成功し、空のアプリをローカル表示できる。

## 3. P0: データモデルと純粋ゲームロジック

UIより先に、副作用のないTypeScriptとして構築します。

- [ ] スキル効果をデータで組み合わせられるEffectモデルとして定義する
- [ ] タイムライン要素、戦闘参加者、状態効果、クールダウン、詠唱、ブレイクの型を定義する
- [ ] 実行時のデータ検証を追加し、重複ID、参照切れ、循環したスキル前提を検出する
- [ ] 表示文言とロジック用データを分離する

### 3.2 バトルエンジン

- [ ] 敵AIの予告済み行動列と対象選択を実装する
- [ ] ダメージ、回復、弱点、軽減、戦闘不能を実装する
- [ ] ディレイ、クールダウン、詠唱、ノックバック、キャンセルを実装する
- [ ] ブレイクゲージ、行動スキップ、タイムライン後退を実装する
- [ ] バフ／デバフの同系統上書きと期限切れを実装する
- [ ] 挑発、かばう、反射、反撃、追撃、罠、時間操作を実装する
- [ ] クレリックの他者蘇生とバーサーカーの自己蘇生だけを許可する

### 3.3 編成ロジック

## 推奨着手順

1. 仕様未確定事項を解消する（M0）。
2. プロジェクト基盤と純粋ロジックを作る（M1）。
3. 第1階層を縦切りで完成させ、面白さとUIを検証する（M2）。
4. 検証済みの型を使ってジョブ、敵、階層、アセットを量産する（M3）。
5. 全編のバランス、互換性、オフライン動作を検証して公開する（M4～M5）。

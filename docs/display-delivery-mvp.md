# 1.6 Relicspire 表示仕様・配信・MVPの範囲

本書は [開発タスク](./tasks.md) の1.6に対応する。[ゲームルール](./game-rules.md)、[育成仕様](./growth-party-rewards.md)、[階層仕様](./floor-content.md)、[保存・復旧仕様](./save-recovery-navigation.md) を前提に、表示・設定・配信・第1階層MVPの範囲を確定する。ここでの完了は仕様決定であり、実装・ブラウザ検証・バランス検証ではない。

## 1. 戦闘情報とタイムライン

### 1.1 常時表示と詳細表示

| 場所 | 表示内容 |
| --- | --- |
| 手番欄 | 操作する味方、現在TU、コマンド・対象・確定・取消。入力時間制限なし |
| 味方欄 | HP数値とゲージ、ジョブ、状態アイコン、次の手番／詠唱発動までのTU |
| 敵欄 | HP数値とゲージ、ブレイク残量、弱点・耐性、次のスキルと対象、現在フェーズ |
| 状態詳細 | familyIdに対応する名称、強度、実際の付与者、期限までのTU、回数／残量、有効または一時無効の理由 |
| 行動詳細 | 威力・計算対象・削り・付随効果・詠唱・D・CD・対象規則、全行動列と全移行条件 |
| 戦闘ログ | TU、行動者、対象、HP・ゲージ変化、妨害・反応・状態・蘇生・勝敗。直近200件を保持、再読み込みでは消去 |

弱点・無効・対象規則・フェーズ条件・状態残量を非公開にしない。遭遇確認でも敵の全行動詳細と報酬を閲覧できる。行動列は先頭から全要素を表示し、現在の列と次の位置を強調する。詠唱中は予約済み行動と、その後の予告を区別する。

### 1.2 バーの表示規則

- 右端が現在TU、左端が現在TU+300。表示座標比率は `1 - clamp(残りTU,0,300)/300` とする。味方は人物番号、敵は敵名と形で識別し、色だけに頼らない。
- 1人につき主アイコン1個。待機は手番、行動可能は右端に「入力待ち／未処理」、詠唱は発動時刻とスキル名、ブレイクは復帰時刻を表示する。
- ブレイク復帰後の次手番は詳細に参考値として併記する。復帰時SPDが変わり得るため確定予定と混同しない。
- 時間停止中は停止解除時刻へ停止マーク付き主アイコンを置く。詳細に凍結した残り手番・詠唱・復帰TUを表示し、停止中の予定を通常の進行アイコンとして流さない。
- 300 TU超は左端に集約し、実際の残りTUを数値表示する。重なるアイコンは味方1→2→3→敵の順に縦にずらす。詠唱完了と手番の実行順はゲームルール2.2節で別途決まる。
- 毒の次回発動、状態期限、罠の期限は詳細一覧に表示する。バーへ全効果のアイコンを並べず、主予定に影響する停止・ブレイクだけを常時表示する。
- 戦闘不能者はバーから外し、味方欄に戦闘不能を表示する。蘇生後に復帰予定を戻す。
- モバイルでは詳細をタップ／キーボード操作で開ける。ホバー専用にせず、数値・対象・確定ボタンを画面幅320 CSS px以上で操作できる配置にする。

## 2. コマンド予測の契約

### 2.1 即時行動と詠唱予約

予測は本エンジンへ現在状態のコピーと候補入力を渡して計算し、本状態・ログ・保存・敵列を変更しない。予測用の別計算式を作らない。

| 区分 | 確定前に表示する内容 | 限界表示 |
| --- | --- | --- |
| 詠唱0の即時行動 | その処理単位全体のHP・ゲージ・状態・後退・CD・次回予定・反射／反撃／追撃・蘇生・勝敗・フェーズ変更 | 「この行動の結果」。以後の他者手番までの勝敗を保証しない |
| 詠唱あり | 予約対象・属性、予定発動TU、CD期限、現状態の能力を使ったダメージ・削り等の参考値 | 「現在の状態での参考値。発動までの行動・効果終了・妨害で変化」 |
| 待機・独立時間操作・強化 | 実際に変わる予定・状態と本人の次回手番 | タイムラインに影響しない補正も説明する |

詠唱参考値は「現在発動した場合」の処理結果として反応・かばうを含めて表示するが、将来の期限を無視した確定値とは呼ばない。発動までを自動シミュレーションして未入力の味方コマンドを勝手に仮定しない。詠唱中に失効する現状態には「発動予定前に期限切れ」、先行する敵行動・毒・停止解除には「先に発生する予定」と時刻を併記する。

### 2.2 罠・期限・フェーズの扱い

- 即時予測では現在TUの前段階で既に終わった期限切れ・定期効果を再実行しない。入力待ちで未処理の他者イベントも割り込ませない。
- 罠の設置自体は即時に確定予測できる。後の罠発動ダメージは将来の設置者能力に依存するため参考値とし、対象・設置期限・開始前トリガー・延期条件を表示する。
- 行動単位の予測では付随効果→反射→反撃→追撃→自己蘇生→勝敗→フェーズ移行をすべて含める。終端の手番はゲームルール11.2節、能力参照は11.5節に従う。
- 同職の再付与では期間だけの変更を表示し、強度・付与者・回数が増えると誤表示しない。無効耐性・不適格対象・属性無効では不成立の理由を表示する。
- 有効な対象がない／CD中のコマンドは選択不可とし理由を表示する。選択取消は時刻・CD・行動列を変えない。

## 3. プレイヤー設定

| 保存キー | 型・許容値 | 既定値 | 適用 |
| --- | --- | --- | --- |
| masterVolume | 整数0～100 | 80 | 全音の総音量 |
| bgmVolume | 整数0～100 | 60 | BGM |
| seVolume | 整数0～100 | 80 | 戦闘・UI効果音 |
| ambientVolume | 整数0～100 | 40 | 環境音 |
| muted | boolean | false | 全音を消す。各音量値は保持 |
| animationSpeed | 0.5、1、2の数値 | 1 | 戦闘・探索の演出速度のみ |
| screenShake | boolean | false | 画面揺れ |
| skipBattleAnimations | boolean | false | 戦闘の移動・攻撃演出を即時完了。結果表示とログは残す |

- 音量は `masterVolume/100 × 種別音量/100` を使い、mutedなら0。ブラウザが音再生を許可するまで無音にし、プレイヤーの操作後に開始する。
- 設定は保存・復旧仕様の設定確定で保存する。スライダーは編集候補を試聴できるが、確定前の値を保存しない。保存失敗・取消では確定値へ戻す。
- 「設定を初期化」は上表の全既定値を候補にし、確定して保存する。新規ゲームは有効な既存設定を引き継ぐ。
- 不正値は保存・復旧仕様5節で該当項目だけ既定値へ修復する。欠落キーも既定値で補う。0.5と2は整数以外を許すanimationSpeedの列挙値として検証する。
- 非表示で戦闘処理・演出・全音を停止し、復帰後は「再開」ボタンを押すまで休止を維持する。音量設定そのものは変更しない。保存中のIndexedDB処理は完了させ、復帰時に結果を表示する。
- 演出スキップ・速度・揺れ・音量はロジックのTU・同着順・ダメージ・CD・入力を変更しない。スキップでも次の入力待ちを飛ばさない。
- OSの動きを減らす設定が有効なら、保存設定を変更せず揺れを抑止し、戦闘・探索の非必須な移動演出を省略する。エンディングのページ進行は常に手動。

## 4. 第1階層MVP

### 4.1 データと実装範囲

| 項目 | 第1階層MVPに含む | 後続制作 |
| --- | --- | --- |
| ジョブ・ツリー | 全8ジョブ、A1/A2/A3/B1/B2/B3の48ノード、全効果と説明 | 6.1で採用率・性能調整、完成アセットへ置換 |
| 上位ノード | 蘇生・停止・かばうもロジック・ツリー・コマンドUIへ接続 | 第1階層の通常プレイで追加ポイントを配らない |
| 装備 | 初期6種類18個とrelic-01-01～05 | 第2～10階の45遺物 |
| 敵・探索 | floor-01、boss-01、guardian-01-01～05、全ヒント・イベント | floor-02～10の実戦データ・画面 |
| 成長 | 初期予算3、boss-01後の予算4・floor-02解放保存 | 第2階層以降への移動・攻略 |
| 拠点・保存 | 全編成編集・20プリセット・通常保存・修復・単一タブ所有 | 実データ版変更に伴う移行追加 |
| 戦闘表示 | 1～3節の表示、予測、全状態、設定 | 全編の操作性・バランス調整 |
| 配信 | MVPリリースの全必須アセットのオフライン準備・更新経路 | 全10階分の必須アセットへ拡張 |

「最小スキルセット」は48ノードの省略版とせず、全8ジョブが第1階層で選択可能な状態を指す。通常の3～4ポイントではA3/B3の累計6に届かないが、UIに費用・前提・性能を表示する。上位ノードの手動検証は開発専用の6／12ポイント戦闘fixtureで行い、公開ゲームの予算やセーブを変更しない。未対応データはゲームルール11.7節に従って拒否する。

MVPにも全10階層・全敵・遺物IDの進行／報酬メタデータを含め、プレイ可能な階層だけを別の収録範囲で制御する。未実装階層を未知IDとして扱わない。MVPではfloor-02解放済みという進行を保存し、一覧に「解放済み・この版では未実装」と表示する。次階層への移動だけを無効にし、第1階層未討伐守護者・拠点を引き続き利用できる。フル版への移行では同じIDと進行を保持し、データ追加に伴ってcontentVersionを増やす。MVPの「第1階層クリア」案内を最終エンディング・boss-10クリア扱いにしない。

### 4.2 既存タスクとの対応

3.1～3.4で全現行Effectと48ノードを検証し、5.2・5.4・5.5で全ジョブUIと第1階層6遭遇を接続する。6.1の「全スキル実装」はMVPで実装済み部分を確認して再制作を避け、全45遺物・全編説明・完成アセット・性能調整を進める。6.2で残り階層、最終ボス・エンディングを接続する。5の完了に全編バランスや全10階の画像完成を要求しない。

## 5. オフライン準備

### 5.1 版ごとの必須一覧

リリースごとにbuildId（ビルド固有ID）、schemaVersion、contentVersion、必須URL・内容ハッシュ・バイト数のマニフェストを生成する。アプリHTML、JS・CSSの全チャンク、ゲームデータ、画像・音声・フォント・アイコンを含める。外部配信に依存する必須URLを設けない。MVPは第1階層まで、完成版は全10階の必須一覧となる。

画面上の「オフライン利用可能」は、現在buildIdの全必須ファイルのキャッシュを照合し、Service Workerがこの配信範囲を制御していると確認した場合だけ表示する。ダウンロード完了イベントだけで完了扱いにしない。セーブが可能かどうかは別表示にし、オフライン準備済みでも保存不能なら1.5の開始制限を適用する。

### 5.2 初回・再試行・起動

| 状態 | 表示と操作 |
| --- | --- |
| 初回準備中 | 「オフライン準備中 n/N件」。転送バイト数が分かる場合は併記。新規ゲーム・探索・戦闘開始は待つ |
| 取得または検証失敗 | 失敗したファイル名と再試行。成功分を保持し、欠落・不一致を再取得。未完了を利用可能と表示しない |
| 準備完了 | 「オフライン利用可能」、開始／続きからを許可（保存・所有権条件は別途必要） |
| オフライン起動・全必須あり | ネットワークを待たず起動、更新チェック失敗でプレイを止めない |
| オフライン起動・必須欠落 | 「必要なデータが不足。接続後に再試行」、新しい進行を開始しない |
| 準備完了後の任意更新失敗 | 現版が完全なら現版を続行し、新版取得を再試行できる |

準備の照合は起動時と戦闘開始前に行う。完了後のプレイは既に取得したデータ・アセットから行い、行動による通信を発生させない。更新検知は起動時・拠点での明示的な「更新確認」時だけ実行し、戦闘中のバックグラウンド更新確認は行わない。ブラウザが後からキャッシュを削除した場合に備え、欠落を検出したら現処理を止めて不足表示を出し、ネットワークへ黙って代替しない。保存済み進行は消さない。

## 6. 新版検知と安全な切替

### 6.1 Service Workerとプレイ中の版を分離

技術方針の `registerType: 'autoUpdate'`、`cleanupOutdatedCaches: true` を採用する。Service Workerの自動更新と、ゲーム画面のリロード・コンテンツ切替を分離し、更新の検知・取得だけで画面をリロードしない。登録コードにも自動のページリロードを入れない。

- 開いているアプリは起動時buildIdとデータ・アセットマニフェストを固定し、新しいWorkerが有効になっても途中で別版のデータを読むことを禁止する。
- プレイ前にその版の全必須ファイルを、Workbox管理キャッシュとは別の `relicspire-release-<buildId>` キャッシュへ保持する。自動の古いWorkboxキャッシュ掃除でアクティブなゲーム版のファイルを失わない構成にする。
- 実行中はハッシュ付き版固有URLのみを使う。Workerの取得処理は稼働中タブが固定した版のリリースキャッシュを参照できるようにし、旧URLへ新しい内容を返さない。HTMLだけを更新して旧JSと組み合わせない。
- 新版が全必須ファイルの検証に成功してから「新版の準備ができました」を表示する。現版と候補版を混ぜて不足を埋めない。
- リリースキャッシュは現版と切替候補版を保持する。古い版の掃除は全タブでその版の利用が終了したことを確認してから行う。タブの応答がない場合は利用終了と推測せず掃除・切替を待つ。再起動後に残る未使用版は生存クライアント確認後に掃除する。

### 6.2 更新を適用できる条件

次の条件をすべて満たすときだけ「保存して更新」を有効にする。

1. 所有タブが拠点にいて、戦闘・エンディング・入力途中の編集・確認ダイアログがない。
2. 保存キューが空、失敗候補・未保存勝利・移行／修復候補がない。
3. 新版の必須ファイルが完全で、対応するWorkerを利用できる。
4. 同じゲームを開いた全タブが切替に応答し、操作停止に同意した状態。未応答・戦闘中なら待つか、ほかのタブを閉じるよう案内する。所有権を横取りしない。

配信状態はIndexedDBの別キー `relicspire-delivery` に、最後に切替確定したbuildIdと対応版を保持する。初回にキーがない場合は全必須検証済みの起動buildIdを所有タブが期待値「不存在」で確定してから初回セーブを許可する。既存キーを起動だけで別版へ上書きしない。これはゲーム進行・previous・プリセット復元の対象外とし、古いセーブの復元で配信版を巻き戻さない。旧タブの書き込み時にもこのキーをトランザクション内で照合する。

適用時は新しい操作を禁止→所有権・revision照合→現版で確定状態を保存→全タブの停止確認→候補buildIdを配信状態へ確定→候補buildIdのHTMLへリロード、の順。保存または配信状態の確定に失敗したら現版に留まり1.5の再試行・取消を使う。配信状態確定後にリロードできなかった場合は更新待ち画面で再試行し、旧版での新規書き込みを再開しない。更新通知の「あとで」は現版を続けるだけで、勝手に次の手番や帰還を実行しない。

新版は起動時にマニフェストの版を確認し、その版のゲームデータだけをロードしてから1.5のセーブ移行を行う。移行が必要なら対応済み移行と確認を経て保存する。失敗・未対応・未来セーブ版なら復旧画面へ留まり進行を書き換えない。別タブは旧版のメモリ状態を再利用せずリロード・最新セーブ読み直しを行う。

新しい起動で旧セーブを読むことは対応済み移行で許可するが、旧アプリが新版セーブを書き戻すことは禁止する。旧版タブが残った場合は表示のみ可能とし、所有権取得前に配信の現在buildIdと一致するか確認して、異なる場合は更新画面へ誘導する。オフラインで新しい配信版を確認できない場合はローカルに最後に確定した配信buildIdを使い、既に新版切替済みと分かる旧版には書き込みを許可しない。

## 7. 受け入れ条件

| ID | 条件 | 期待結果 |
| --- | --- | --- |
| U01 | 次回予定が400 TU後、他者と同着 | 左端に400表示、重なりを参加者順に分離。判定順はエンジンどおり |
| U02 | 停止中に詠唱の残りTUがある | 停止解除を主表示、詠唱残りは凍結値で表示 |
| U03 | 即時攻撃で反撃・自己蘇生・フェーズ変更が起こる | 処理単位末尾までの予測と実結果が一致し、本状態を変えない |
| U04 | 詠唱前の強化が発動前に期限切れ | 参考値表示と期限警告、確定ダメージと表示しない |
| U05 | 演出速度・音量・スキップを変えて同じ入力列 | 同じTU・HP・CD・ログ内容。次の入力待ちは残る |
| U06 | 非表示から復帰 | 再開入力まで時間・音・演出停止、保存完了は表示 |
| U07 | MVP初期3ポイント、上位6ポイントノード | 性能・前提を閲覧可、予算不足で習得不可。開発fixtureでは効果を検証 |
| U08 | MVPでboss-01勝利 | 予算4、floor-02解放を保存、未実装階へ移動しない |
| U09 | 初回アセットの一部が失敗 | 未完了表示、開始を待ち、再試行で欠落だけ取得 |
| U10 | 新Worker有効化中に戦闘・未保存報酬がある | 旧buildIdで継続／保存失敗処理を維持、自動リロードなし |
| U11 | 新版切替保存成功後に旧タブが所有権を取り直す | 版確認で書込拒否、リロード後に最新セーブを読む |
| U12 | キャッシュ欠落・未来版セーブ | 不足／復旧表示、別版を混ぜずセーブを上書きしない |

表示・設定は1～3節、MVPは4節、初回オフライン・新版適用は5～6節で定義した。ブラウザでのWorker更新・複数タブ・キャッシュ掃除とセーブ版の組合せはタスク8の必須統合検証とし、仕様だけで動作保証済みにはしない。

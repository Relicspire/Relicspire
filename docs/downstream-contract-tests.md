# 3.9 後続接続の契約テスト

`src/game/contracts/downstream.test.ts`で3.5～3.8の公開APIをつないで検証する。既存の単体テストは維持し、UI・IndexedDBなしで後続の保存・表示コードが依存する境界を固定する。入力を再帰的に凍結し、コピー生成前の書き込みも検出する。

## 追加した接続テスト

| 接続 | 検証内容 |
| --- | --- |
| MVP読み込み→探索→予測→実戦勝利→進行候補 | 正式リリース検証、親分岐の開始前進行、即時予測と実行の一致、戦闘報酬と進行候補の一致、floor-02解放の維持と未収録移動の拒否 |
| 候補破棄→再試行 | 保存失敗を想定して候補を破棄・変更しても開始前進行は不変。同じ開始前入力から再生成でき、更新済み進行への再報酬は拒否 |
| MVP進行→フル版→最終勝利 | 同じ全編ID・報酬メタデータで解放を引き継ぐ。守護者なしで探索・戦闘・出口・次階層を10回接続し、最終候補はguild・結末未処理・予算12。遺物は未取得のまま |
| 正式データ・進行検証→操作拒否 | 誤報酬、収録ジョブ欠落、到達不能を読み込み時に拒否。未知討伐・ボス順序の穴・未解放守護者の進行は移動前に拒否 |
| 詠唱予約→失効表示→実発動→演出差分 | 現在強化による参考値と失効後の実ダメージを区別し、参考値を将来確定値にしない。期限切れと発動ログを連番カーソルと前後差分の双方で取得 |
| 表示・予測→取消→実行 | 表示コピーや予測候補を変更・破棄しても戦闘・全ログ・取得カーソルは不変。表示200件制限後も全ログと次の演出差分を保持 |
| 現在編成復旧→再検証→戦闘開始 | 予算超過の本人だけ全解除した候補を戦闘へ渡せる。同じ旧プリセットは無効として保持し、現在進行のロードを一律に止めない。候補を変更しても原本・進行は不変 |

## 3.9各項目の検証先

| 項目 | テストファイル |
| --- | --- |
| 全編ID・MVP範囲・正式欠落・到達不能・誤報酬 | `data/release.test.ts`、`contracts/downstream.test.ts` |
| 討伐順・未知ID・報酬重複・守護者回避・非再出現・再訪・親分岐・最終候補 | `progression/progression.test.ts`、`contracts/downstream.test.ts` |
| 即時予測と実行・詠唱参考値・先行イベント・失効・罠・反応・停止・ブレイク・フェーズ・ログ | `battle/queries.test.ts`、`contracts/downstream.test.ts` |
| 現在編成復旧と旧プリセットの差・未知職初期化・全解除・集合管理・原本分離 | `party/recovery.test.ts`、`contracts/downstream.test.ts` |

ファイルの接頭辞は`src/game/`。各テストの意図・期待結果は日本語の`describe`・`it`で記述する。

10階層接続には、戦闘を速く終わらせるためHP1の合成敵を使う。正式な攻略可能性・性能・バランスを保証するテストではない。保存失敗の検証も候補の破棄と非変更の契約であり、IndexedDBトランザクション失敗の再現ではない。保存競合・原子的更新は4、画面・ブラウザ遷移は5・7、PWAと配信は8、全編バランスは7.1で検証する。

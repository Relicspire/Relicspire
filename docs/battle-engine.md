# 3.2 バトルエンジン

`src/game/battle/index.ts`を入口に、描画・React・Zustand・ストレージから独立した純粋なTypeScriptの戦闘APIを提供する。各更新はセッションをコピーして実行し、入力セッション、コンテンツ、戦闘前の進行スナップショットを変更しない。時間は整数TUのみで進み、実時間・乱数・演出速度には依存しない。

## 呼び出し方

```ts
import {
  createBattle,
  getInputActor,
  submitCommand,
  getBattleOutcome,
} from '../src/game/battle';

// content: 検証対象のGameContent、setup: 3人の確定編成と敵ID
// committedProgress: 戦闘開始前に保存完了した進行。エンジンはこの中身を扱わない。
let session = createBattle(content, setup, committedProgress);
const actorId = getInputActor(session);
if (actorId !== null) {
  const result = submitCommand(session, {
    actorId,
    skillId: 'basic-attack',
    selectedTargetId: setup.enemyId,
    chosenElement: null,
  });
  if (result.ok) session = result.session;
}
const outcome = getBattleOutcome(session);
```

| API | 契約 |
| --- | --- |
| `createBattle` | コンテンツと編成の予算・所持数・前提を実行時検証し、party-1→2→3→敵の順に初期化。全快・状態なし・CDなしのTU0状態を保持し、最初の入力または終了まで進む |
| `getInputActor` | 入力待ちのキャラクターID。未到達・敵・終了ならnull |
| `checkCommand` | 手番・習得・上位置換・CD・属性選択・対象適格性を検証 |
| `getSkillTargets` | 現在の適格な対象IDを参加者順で返す。全体／自身スキルのコマンドではselectedTargetIdをnullにする |
| `submitCommand` | コマンドを原子的に確定し、自動イベントを次の味方入力か終了まで処理。不正なら元のセッションをそのまま返す |
| `advanceBattle` | 未処理イベントを入力か終了まで処理。入力待ちに再度呼んでも進まない |
| `getEnemyForecast` | 現在の行動列、明示規則、挑発から単体対象を計算。詠唱中は予約済みスキル・対象を保持。停止中は絶対時刻を予測せず凍結残りTUを返す |
| `escapeBattle` | 処理単位の間で逃走を確定し、全予定を破棄。既に終了している場合は勝敗を優先 |
| `retryBattle` | 勝利以外なら、開始時の編成・全快・状態なし・CDなし・TU0から再初期化し、最初の入力まで進む |
| `getBattleOutcome` | 勝利だけに報酬候補を付け、呼び出し元の戦闘前スナップショットのコピーを返す |
| `getDebugSnapshot` | 状態と時刻・連番付き構造化ログのコピー。JSONで記録可能 |

演出を同期させる場合、`submitCommand(..., { advance: false })`で確定した処理だけを実行する。演出後に`advanceBattle(..., { stopAfterUnit: true })`を呼ぶと、期限切れなどを処理した後、罠1個・同時刻の定期効果全体・詠唱発動・敵コマンドのいずれか1処理単位、または味方入力で停止する。これらの境界で逃走・リトライを適用できる。自動進行と段階進行は同じ状態・ログを生成する。UIの演出待ち中は更新APIを呼ばない。

## 処理の規則

有効なタイマーからタイムラインを再構築し、TU→停止解除→通常期限切れ→ブレイク復帰→定期効果→詠唱完了→手番→参加者順→付与順で解決する。更新された予定のイベントIDは維持し、消えた予定は実行しない。入力中には同じTUの後続参加者も処理しない。

発動直前に行動者能力・HP条件・全体対象集合を保存する。Effectの記載順に、各対象の現在の適格性と防御を確認して実行する。攻撃はかばう→反射資格保存→HP減少／死亡→生存敵のゲージ削り／ブレイク→後退→キャンセル→付随状態→解除→反射→反撃。全Effect後に追撃、自己蘇生、勝敗、フェーズ、終了待機を処理する。反応は新しい反応を発生させない。

能力・ダメージ・回復・速度はゲームルール3節を適用する。参加者のstatsは装備加算後の基礎値（最大HPのみ確定上限へ制限）であり、表示・判定にはeffectiveStatsを使って補正後に上限・下限を適用する。ダメージ・回復・削りの乗算は整数の分数として計算して最後に切り捨てる。時間は切り上げる。攻撃属性無効では削り・付随効果も成立しない。無属性は常に通常倍率。

同系統再付与は付与者・強度・付与連番・残り回数・毒の周期を保持し、期限だけ更新する。停止は行動・CD・通常状態・毒・本人の罠のタイマーを凍結する。死亡時にはCDだけを死亡時刻から復元し、ほかの予定を削除する。蘇生後の50 TU待機やブレイク復帰は通常ディレイで上書きしない。

終端は`finished`状態として行動予定・状態・CD・罠・タイムラインを破棄し、結果表示用の最終HPを保持する。戦闘外HPの全快、敗北・逃走時の探索位置復元は呼び出し元がpreBattleと確定進行から導出する。

## 実装範囲と検証

現行Effect全種、1敵・3味方、1攻撃Effect1ヒット、固定行動列とHPフェーズ、クレリックの他者蘇生／バーサーカーの自己蘇生を実装した。通常攻撃・待機は固定の無料コマンドとして提供し、コンテンツに記載する場合も固定定義からの変更を拒否する。現行の敵スキルはCD0・属性選択なしを検証する。B18の無効検証用にEnemyDefinitionへ省略可能なimmuneElementsを追加し、弱点・耐性・無効の重複と無属性指定を拒否する。正式な60遭遇はこのフィールドを省略できる。

VitestはUIなしの勝利までのサンプル戦闘、同着・相打ち、不正コマンドの非更新、処理単位ごとの進行との同一性、ゲームルール11.8の現行境界例、特殊効果と停止・蘇生の相互作用を固定する。合成したテスト用コンテンツを使い、正式な全編コンテンツの投入やバランス調整は後続タスクで行う。

編成予算・所持品は3.3の共通検証を戦闘開始時にも適用する。`setup.context`に検証済みの討伐IDと`inBattle: false`を渡す。省略時は初期予算3・守護者未討伐として検証する。プリセットAPIは[編成ロジック](party-formation.md)を参照。全編ロジックテストの拡充は3.4、報酬の一度だけの原子的保存・復旧は4、画面と演出の接続は5以降の対象。エンジンの報酬候補を取得するだけでは進行やセーブは更新されない。

正式リリースの実戦データを使用する場合は`setup.campaign`に全編メタデータを渡す。第1階層のみのMVPでも、未収録のfloor-02への解放報酬を正規IDとして検証できる。リリース全体は事前に`parseGameRelease`で検証する。

3.7のコマンド予測・表示照会・ログ差分APIは[戦闘照会](battle-queries.md)を参照。使用不能判定に安定した`code`を追加し、従来の`reason`も保持する。

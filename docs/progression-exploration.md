# 3.6 進行・報酬・探索の純粋ロジック

保存層向けのID移行と進行修復は3.12の[進行移行・復旧候補](progression-recovery.md)を使う。通常検証・移動の拒否規則は変更しない。

入口は`src/game/progression/index.ts`。検証済みの`GameRelease`を使用し、UI・時計・乱数・保存処理に依存しない。操作は`ProgressionResult`で候補またはパス付き拒否理由を返し、元の進行・リリースを変更しない。

## 保存対象と導出

`Progression`は討伐済み敵ID、初訪問済み階層ID、`endingHandled`、`location`だけを保持する。位置は`guild`または階層ID・ノードIDの組で表す。編成・設定・saveId・版・revisionは保存層で組み合わせる。

`createInitialProgression()`は未討伐・未訪問・結末未処理・拠点の状態を返す。`deriveProgression(campaign, progression)`は全編メタデータから解放階層・最終クリア・個人予算・全編の所持数を導出する。未収録遺物もIDと所持数を保持する。

予算・所持数は`getCampaignSkillPointLimit`と`getCampaignInventory`を共用する。編成APIの`getSkillPointLimit(context, campaign)`、`getInventory(content, context, campaign)`にも同じメタデータを渡せる。従来の部分カタログではメタデータ引数を省略できる。

`validateProgression(campaign, unknown)`は構造、重複、未知ID、先行ボスの穴、未解放階層の守護者討伐、訪問・復帰先、クリア前の結末処理を確認する。生存敵の部屋は保存復帰先として拒否する。既知の未収録階層は進行IDとして維持できるが、その位置での通常操作は収録確認により拒否する。

`normalizeProgression`は重複だけを除いた独立候補を再検証して返す。未知IDや討伐の穴、位置・設定の修復は行わない。正常化候補の表示・保存確定は保存層が担当する。

## 探索と遭遇

| API | 契約 |
| --- | --- |
| `warpToFloor` | 拠点から解放・収録済み階層の入口へ移動候補を生成 |
| `selectNode` | 同階層の隣接部屋を選択。生存敵なら通常移動を確定せず遭遇確認を返す |
| `returnToGuild` | 戦闘外の有効な位置から拠点へ帰還する候補 |
| `moveToNextFloor` | 討伐済みボスの出口から次階層入口へ移動。最終階層には次階層なし |
| `validateEncounter` | 開始前の親分岐、隣接する敵部屋、敵ID・所属、未討伐を照合 |
| `leaveEncounter` | 回避・敗北・逃走用に、開始前の親分岐を持つ進行コピーを返す |
| `getFloorAccess` | 階層一覧の解放・収録・ワープ可否・訪問・ヒント解放を導出 |

通常移動の結果は`ExplorationCandidate`で返す。入口を初めて訪れる候補は訪問IDを追加し、`showEntryText: true`とする。入口文を表示するのは候補の保存成功後。失敗して候補を破棄した場合は元の未訪問状態が残る。再訪でも入口文・ヒントの任意再閲覧は可能。

生存敵を選ぶと`encounter`に敵ID・部屋・親分岐を返し、`progression.location`は親分岐のまま。遭遇確認は保存対象ではない。討伐済み部屋の選択は通常移動となり、遭遇・再戦・追加報酬は生成しない。守護者の回避で主経路を妨げない。

## 勝利候補と保存境界

`createVictoryCandidate(release, preBattle, encounter, enemyId)`は戦闘開始前に保存済みの進行を使う。呼出元が戦闘結果の勝利を確認し、その敵IDを渡す。APIは遭遇と敵IDを照合して討伐を1件だけ追加し、報酬の導出結果と次の保存候補を一括で返す。既討伐の敵、異なる勝利ID、変更された親分岐・部屋は拒否する。

通常勝利の復帰先は討伐した部屋。最終ボス勝利は拠点へ戻り、`endingHandled: false`とする。報酬は加算済み残高ではなく討伐集合から導出するため、同じ開始前入力の再試行は同じ候補となる。更新後の進行に同じ報酬を再適用する操作は拒否する。

MVPのboss-01勝利は予算4・floor-02解放を保持する。floor-02が未収録なら移動だけを拒否し、第1階層の残る守護者と拠点を利用できる。

ここでの成功は保存完了を意味しない。保存包・revision照合・競合制御・原子的確定・戦闘開始制限・結果画面からの遷移はタスク4が接続する。未保存勝利候補の破棄では開始前進行をそのまま使用する。現在編成やプリセットの復旧は3.8の対象。

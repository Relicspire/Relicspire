# バトルUIの接続契約

`src/features/battle/`を共通UIの現在地へ接続する。戦闘セッションまたは保存済み報酬表示がある間は探索・ギルドより優先する。正式リリース／配信準備の起動ゲートは維持し、テスト用カタログを製品へ組み込まない。

## 操作と進行

- 遭遇確認の「戦う」は既存の`startBattle`で戦闘前保存の成功後だけセッションを公開する。遭遇確認でも全敵行動列・移行条件・スキル性能・妨害耐性を閲覧できる。
- `getBattleDisplay`・`getCommandDetails`・`previewCommand`を表示へ使用する。習得済みの最上位コマンド、通常攻撃、待機を列挙し、CD中／対象なしの理由を表示する。対象と属性の選択・取消は純粋な予測だけを行う。
- `game.command`は`submitCommand(..., { advance: false })`で処理単位を確定する。次の予定は`game.advance`と`advanceBattle(..., { stopAfterUnit: true })`で進める。味方入力待ちへ到達したら自動進行を止める。
- 自動進行は演出の長さに合わせて待つ。省略設定と端末の動きを減らす設定では待ちを省略する。ロジックのTU・計算式・同着順は変えない。
- 古いセッションを持つコールバック、保存中・読取専用・所有権喪失・手動休止中の操作は状態管理器でも拒否する。復元の非同期読取中は共通メニューとセーブ操作を禁止し、読取後に所有権・保存状態を再確認する。
- 手動休止はメモリの戦闘Storeで保持し、設定画面へ移動して戻っても保持する。非表示時は共通UIの再開入力まで自動進行・PixiJSを止める。Effectのタイマーを破棄し、発火時にもvisibilityを確認する。
- 戻るキー・Alt+左・ブラウザ履歴で戦闘を休止し、続行・同編成リトライ・逃走を選ぶ。勝利保存待ちでは別画面へ移動しない。

## 表示と予測

300 TUの一本バーは右端が現在TU、左端が現在TU+300。主アイコンは1人1個、参加者順で縦位置を分ける。300超は左端へ集約し実際の残りTUを併記する。名前と数値を別行にして長い敵名でTUを隠さない。形と人物番号も付け、色だけに依存しない。

詠唱はスキル・発動予定、停止は解除時刻・凍結残り、ブレイクは復帰・その後の待機参考値を表示する。戦闘不能者はバーから除外する。詳細一覧の同着順は予定種別と参加者順に従う。

HP・ゲージ、ジョブ、現在手番、状態名、次の予定を表示する。状態詳細には性能・実付与者・残り期限・凍結・周期発動・回数・解除可否・一時無効理由を表示する。敵予告は予約済み詠唱とその後の列を区別し、全フェーズ・全移行条件・全行動性能を開示する。

即時予測は「この行動の結果」、詠唱予測は「現在の状態での参考値」と区別する。差分・反応・自己蘇生・フェーズ・勝敗・CD・予定・付随効果と不成立理由を表示し、未来の味方入力を仮定しない。詠唱前の状態失効と先行イベントには時刻を示す。罠は設置の結果と将来発動の参考値・期限・延期条件を区別する。同系統再付与の期限延長を強度・付与者・残回数の変更と誤表示しない。

実行ログは直近200件を表示する。処理単位のHP・ゲージ差分と効果診断も表示する。終了・再読込・所有権喪失で一時戦闘情報を解除し、保存対象には追加しない。

## 結果と保存

- 勝利成立時に`victory`を呼び、保存中は操作を禁止する。成功時だけ報酬表示用の一時receiptを発行し、遺物・各人のポイント・階層解放を獲得済みとして表示する。
- 保存失敗時は共通セーブ管理の再試行と放棄確認へ接続する。取消は実際のDBを照合し、保存済みなら勝利を確定する。未保存ならセッション・遭遇を解除して親分岐へ戻す。報酬・討伐を重複追加しない。
- 敗北・逃走は報酬を与えず、開始前の編成・進行と最新設定を復元する。探索の親分岐、拠点帰還、同編成リトライを選べる。帰還の現在地は通常の保存成功後に確定する。
- 勝利保存が済むまで新規開始・previous復元・移動を提供しない。保存成功後の「探索を続ける」で討伐部屋へ戻り、通常の帰還・次階層操作を使う。boss-01は第1階層クリア表示とし、最終クリアにしない。

## PixiJS

探索の描画基盤を共有し、ログの効果連番を一方向に渡す。攻撃・回復・妨害／詠唱・ブレイク・戦闘不能を色のフラッシュと図形で演出する。ダメージ時の揺れは設定で有効化し、動きを減らす設定で省略する。DOMの結果表示・ログを必ず残す。描画から命中・HP・ゲージ・TUを変更しない。完成アセットと音声制作は6.3。

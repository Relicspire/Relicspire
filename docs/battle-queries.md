# 3.7 戦闘予測・表示用の照会API

3.11で効果単位の実処理診断を追加した。`BattleDelta.effectResults`と診断カーソルの使い方は[効果結果](effect-results.md)を参照。入力前の警告と処理時の成立・不成立理由を区別して取得できる。

入口は`src/game/battle/index.ts`、実装は`queries.ts`。全APIは現在のセッションを変更せず、コピーした表示データを返す。時計・保存・DOM・描画には依存しない。

## コマンド予測

`previewCommand(session, command)`は入力候補を本エンジンで検証・実行する。拒否時は`ok: false`と使用不能理由コードを返す。

| 返却項目 | 契約 |
| --- | --- |
| `kind` | 即時行動は`immediate`、詠唱予約は`casting` |
| `committed` | 今コマンドを確定した1処理単位の前後状態とログ差分。即時は付随効果・反射・反撃・追撃・自己蘇生・勝敗・フェーズまで含む。詠唱は予約とCDだけ |
| `reference` | 詠唱を現在TU・現在能力・現在状態で発動した場合の参考結果。即時行動はnull |
| `activationAt` / `cooldown` | 予約の予定発動TUと実際の共有CDタイマー |
| `precedingEvents` | 予約済み詠唱より前の有効なイベント。期限と同着優先順を反映する。未入力の味方行動を仮定しない |
| `expiringStatuses` | 予定発動TUまでに通常期限が来る状態。停止中の凍結期限を通常期限と混同しない |
| `warnings` | 現在の被弾者に対する属性無効・停止無効・キャンセル無効・詠唱なしの参考理由コード |
| `trapReferences` | この入力で設置した罠の、現在能力で発動した場合の参考結果 |

即時の`committed`は`submitCommand(session, command, { advance: false })`と一致する。予測で後続の自動イベントは進めず、同じTUの未処理の他者入力も割り込ませない。差分には参加者のHP・ゲージ変化、状態・能力・行動予定・CD・敵列の前後、罠・結果・タイムラインの状態コピーを含める。

詠唱参考値は現在TUの1処理単位を評価したもの。発動時点の確定値ではない。発動までの毒、状態終了、停止解除、敵行動、入力によって結果は変わる。参考値のログを本ログへ追加せず、同じ戦闘計算を使用する。

`getTrapReference(session, sequence)`は指定の設置罠1個について、敵が今行動開始したと仮定した開始前トリガーを本エンジンで処理する。設置者の能力は現在値。設置者が死亡・停止・ブレイク中なら理由とnullを返す。他の罠や将来の行動を進めないため、将来の連続罠の確定予測には使用しない。

`getEffectWarnings`は現在の属性と妨害耐性を照会する。単体攻撃は現在有効なかばう役の耐性を使う。属性無効は付随効果も抑止されるため属性無効だけを返す。効果順で対象が死亡・ブレイクする場合の最終結果は`committed`／`reference`の状態とイベント差分を参照する。

## 表示用照会

| API | 内容 |
| --- | --- |
| `getMainSchedules` | 生存・継続中の参加者ごとに主予定1個。停止は解除時刻と凍結残りTU、ブレイクは復帰時刻と現在SPDによる復帰後待機参考値。死者・終了済みは除外 |
| `getStatusDetails` | 状態性能、実際の付与者、残りTU・周期・回数・凍結状態、一時無効理由 |
| `getEnemyDetails` | 全敵能力・耐性・全フェーズ・全行動列、現在予告、予約済み詠唱と次の列を分離 |
| `getCommandDetails` | 候補入力の使用可否、スキル定義、適格対象、残りCD、現在SPDによるディレイ参考値 |
| `getBattleDisplay` | 全参加者の現在能力・状態・有効コマンド、主予定、敵詳細、罠をまとめて照会 |

反射・反撃・追撃の無効理由は所持者の停止・ブレイク等、かばうは実付与者の状態、挑発は実付与者の死亡を参照する。毒や能力補正は停止で凍結しても他者からの効果を受けるため、一律に「停止中は全状態無効」としない。

`checkCommand`と拒否時の`submitCommand`にも`code`を追加した。既存のデバッグ用`reason`は保持する。コードは`not-awaiting-input`、`unknown-skill`、`not-learned`、`replaced`、`cooldown`、`invalid-element`、`unexpected-target`、`invalid-target`。日本語表示文言はUI側で対応付ける。

## 演出・ログの接続

`getBattleDelta(before, after)`は1回の更新の前後比較を返す。演出側は`submitCommand(..., { advance: false })`、`advanceBattle(..., { stopAfterUnit: true })`の境界で取得する。まとめて自動進行した2状態を比較した場合は、その間の全処理の差分になる。

`getBattleEvents(session, afterSequence)`は指定ログ連番より後のイベントを、元の順序で返す。開始時は0、次回は取得済みの最後の連番を渡す。リトライなど履歴を置き換えたときはカーソルをリセットする。全ログは削除しない。

`getDisplayLog(session)`は独立コピーの直近200件だけを返す。`session.log`全体はデバッグ・再現・集計用に保持する。表示側の200件上限を戦闘判定やログ連番へ影響させない。

## 検証

`queries.test.ts`で即時予測と実行の一致、入力の非変更、詠唱予約・参考値・失効・先行イベント、反射・反撃・追撃・勝敗・ブレイク・フェーズ・自己蘇生、罠、安定した拒否・無効理由、停止・状態・敵列の表示、ログ差分と200件上限を確認する。DOM・バーの300 TU座標・日本語表示・演出との接続は5.4の対象。

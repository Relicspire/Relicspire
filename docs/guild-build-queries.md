# 拠点の能力値・スキル性能照会

`src/game/party`から`getBuildStats`と`getGuildBuildDetails`を公開する。検証済みのカタログと編成を渡す。所持数・習得予算・前提の確定検証には従来の`validateFormation`や編集APIを使う。装備変更候補の比較にも使えるよう、能力値集計そのものは所持数を判定しない。未知人物・装備・ジョブ・欠落スキル、6枠以外の装備は例外で拒否する。

## 能力値

`getBuildStats(content, build)`は次の独立したコピーを返す。

| フィールド | 内容 |
| --- | --- |
| `baseStats` | 人物の基礎能力 |
| `equipmentStats` | 全6枠を加算した能力。集中装備は個数分加算する |
| `effectiveStats` | 状態補正なしで上下限を適用した能力 |
| `initialWait` | 実効SPDによる開始待機TU |

戦闘初期化もこの集計を使用する。戦闘参加者には、将来の強化・弱体計算用の装備加算値を保持し、最大HPだけ確定上限へ補正する。拠点の実効能力は戦闘開始時の`effectiveStats`と一致する。

## 全ノードの閲覧

`getGuildBuildDetails(content, build, context, options?)`は選択ジョブのA1〜A3、B1〜B3を順に返す。未習得や予算不足でも閲覧できる。各結果の`node`・`skill`はコピーした定義で、費用・前提・置換グループ、対象、属性候補、詠唱TU、基礎CDと共有ID、全効果・付随効果・状態強度・期限を参照できる。

`learned`、`activeCommand`、`replacedBy`、`missingPrerequisites`、`remainingPoints`、`canLearn`を導出する。`canLearn`は検証済み編成での前提・個人予算・未習得・戦闘外という条件の表示用判定であり、習得操作の代わりにはならない。閲覧しても未習得コマンドは戦闘で実行できない。`delayReference`は現在装備の実効SPDを共通のディレイ式へ適用した参考TUで、詠唱と基礎CDは速度で短縮しない。

## 効果の参考値と条件

行動者は現在編成の装備反映後の能力を使い、状態補正なし・与ダメージ／回復補正1倍とする。`options`には背水用の`actorHp`、`chosenElement`、対象束縛別の`targets`を指定できる。HP指定は0〜実効最大HPの安全な整数でなければ拒否する。

対象には`participant`（能力・状態・行動状態）と`enemy`（敵定義、耐性なしの対象ならnull）を渡す。対象の能力と敵定義は同一の参照条件を表すものを呼び出し元で用意する。`self`は本人の実効能力・状態なしを自動的に参照する。全体効果への対象指定は代表1人分であり、全体の合計値ではない。

| 効果 | `hpAmount` / `breakAmount` |
| --- | --- |
| 攻撃 | 対象・属性・必要なら背水HPを指定した場合のダメージと敵ゲージ削り。属性無効なら両方0 |
| 回復 | 不足HPへの制限前の回復性能。満タン時の実回復量ではない |
| 蘇生 | 対象最大HPに対する復帰HP。対象適格性は判定しない |
| 罠 | 現在編成・指定対象の状態が発動時にも同じだった場合の攻撃性能。設置時のダメージではない |
| その他 | 数値結果はnull。コピーされた効果定義から固定TU・解除数・状態性能を参照する |

`missing`は必要な未指定条件（`target`、`element`、`actor-hp`）を返す。指定属性が当該スキルの選択肢にない場合も`element`となる。未指定のダメージは0ではなくnull。味方対象のゲージ削りも該当しないためnull。

結果の`reference: 'independent-effects-without-actor-statuses'`とコピーされた`conditions`が参考値の前提を示す。各効果は同じ指定条件から独立して評価し、先行効果・対象の適格性・かばう・反応・実際の失効・将来行動はシミュレートしない。HP上限による実損失制限も適用しない。実行の確定予測や詠唱の発動参考結果には3.7の`previewCommand`を使う。

能力値・ディレイ・攻撃・回復・蘇生HPの式は戦闘と共有する。日本語名のテストで、戦闘開始との一致、単独攻撃の実行との一致、空欄・集中装備・上下限、未習得／置換ノード、対象・属性・背水条件、罠・回復・蘇生と入力の非変更を検証する。

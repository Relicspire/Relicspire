# 3.3 編成ロジック

`src/game/party/index.ts`を入口に、UI・状態管理・保存から独立した純粋なTypeScript APIを提供する。型・定数・関数の役割と引数には日本語コメントを付けている。

## 状態と検証

`FormationState`は固定順の3人編成とプリセットを保持する。`FormationContext`は検証済みの討伐ID集合と戦闘中フラグを渡す。コンテンツは`parseGameContent`で事前検証する。進行データ自体の復旧・移行は保存層の対象であり、このAPIでは未知の討伐IDを補正しない。

各人物の予算は初期3にボス01〜09の異なる討伐数を加え、最大12。所持数は初期装備の定義と遺物の入手元守護者の討伐から導出する。残りポイント・所持数・戦闘中HPは編成に重複保存しない。

`validateFormation(content, candidate, context)`は人物の順序、ジョブ、前提、重複ノード、個人予算、6装備枠、全18枠の所持数、遺物のユニーク制約を確認し、パス・コード・日本語メッセージを返す。更新APIは`FormationResult`を返し、成功時だけ独立した状態コピーを生成する。不正な候補は入力状態を変更しない。戦闘中の編成変更とプリセット呼出は拒否する。

## 編成API

| API | 動作 |
| --- | --- |
| `createInitialFormation` | カタログの3人の初期ジョブ・習得・装備を検証して生成 |
| `replaceParty` | 3人分の候補を一括検証して確定 |
| `changeJob` | 同職重複を許可。別ジョブへの変更は本人の習得を全解除 |
| `learnSkill` | 前提と個人予算を確認してノードを購入 |
| `getSkillRefund` / `removeSkill` | 指定ノードと前提を失う子孫の解除・返却費用をプレビュー／適用 |
| `resetSkills` | 本人の習得を全解除 |
| `getActiveSkillIds` | 無料の通常攻撃・待機と有効コマンドを返す。同じ置換グループ内は最高ランクのみ表示 |
| `getSkillPointLimit` / `getSpentSkillPoints` / `getRemainingSkillPoints` | 予算・使用・残りポイントを導出 |
| `getInventory` | 進行とカタログから所持数を導出 |
| `setEquipment` | 指定人物の0〜5の枠へ装備、またはnullで解除 |
| `transferEquipment` | 移動元と移動先を同時更新。既定のmoveは移動先の旧装備を外し、swapは交換 |

装備のジョブ・部位制限は設けない。同じ初期装備を所持数まで1人へ集中できる。上位置換はコマンド一覧だけに適用し、購入済み下位ノードと費用は保持する。ランク3が別グループならランク2と共存する。バトルエンジンも同じ有効コマンド判定と編成検証を使用する。

## プリセットAPI

`createPreset`、`renamePreset`、`overwritePreset`、`deletePreset`、`recallPreset`で管理する。`validatePreset`は保存候補のメタデータと編成を検証する。最大20件、IDは一意。同名は許可し、更新日時の降順・同時刻はIDの昇順に整列する。

名前は前後空白の除去とNFC正規化後に1〜24 Unicodeコードポイント。制御文字は拒否する。ID・UTC Unixミリ秒の時刻・非負整数のコンテンツ版は呼出元が渡すため、内部では時計や乱数を使用しない。プリセットには編成と管理メタデータだけを保存する。上書きは作成日時とIDを保持する。

旧版プリセットは通常呼出で不整合を拒否し、原本を保持する。`previewPresetRepair`は削除済み・他職のスキルと前提を失う子孫を除外し、未所持・超過装備を人物順・枠順に外す。変更差分と残る問題を返す。未知ジョブや予算超過は自動修復しない。

ID変更は明示した`PresetIdMigration`の対応表で移行する。修復の適用はUIで候補を確認した後に`recallPreset`の修復オプションを指定する。呼出後も保存済みプリセット原本は変更しない。永続化と確認UIの接続は後続タスクで行う。

## 検証

Vitestで同職3人、独立予算、前提・連鎖返却、上位置換、集中装備、遺物の移動、プリセット各操作・名前・件数・旧版修復・不正データ拒否・入力の非変更を確認する。戦闘開始との統合テストでは能力値への装備反映と、予算超過・未所持装備・所持数超過の拒否を確認する。

3.6の進行APIと全編の報酬導出を共用する場合は、`getSkillPointLimit`と`getInventory`の省略可能な引数に`CampaignMetadata`を渡す。全編メタデータ付きの所持数照会は未収録遺物も含む。

3.8の現在編成専用の復旧候補とプリセット集合の読み込み診断は[編成復旧](party-recovery.md)を参照。旧プリセットの未知ジョブ・予算超過を自動修復しない契約は維持する。
